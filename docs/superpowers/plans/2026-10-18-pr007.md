# PR-007 Guest Checkout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A supporter can tip from a prebuilt `/@handle` page through a pretend provider, see a verified status screen and, if they opted in, a device-only celebration, with no real money.

**Architecture:** The API gains public `/v1` quote, intent and status routes (CORS for `WEB_ORIGIN`, Redis rate limits, HMAC status tokens) plus dev-only mock-checkout routes; the worker gains stale-tip expiry inside reconciliation. The web keeps prebuilt profiles and adds client islands for the quote/tip form, the `/tip/[tipId]` status page and the `/mock-checkout/[reference]` page, plus a tiny local recognition store.

**Tech Stack:** Existing pins only (Next 16.4.2, Nest 12.1.3, drizzle-orm 0.45.3, BullMQ 6.3.11, ioredis 5.11.1, zod 4.6.7, Playwright 1.64.1, @axe-core/playwright 4.14.0).

**Spec:** `docs/superpowers/specs/2026-10-18-pr007-checkout-design.md`

## Global Constraints

- No new dependencies.
- Envelope `{ data }` / `{ error }` on all `/v1` routes; amounts as decimal strings on the wire; currency `NGN` only (illustrative).
- Status token = base64url `HMAC-SHA256(STATUS_TOKEN_SECRET, tipId)`, compared in constant time; secret ≥ 32 chars; never logged; carried only in the URL fragment `#t=` and the `Authorization: Bearer` header.
- Wrong/missing status token → 404 `NOT_FOUND`. Status responses never include the message; `Cache-Control: private, no-store`.
- Error mapping: `IDEMPOTENCY_CONFLICT`, `QUOTE_EXPIRED`, `QUOTE_ALREADY_USED` → 409; `PROFILE_NOT_FOUND` → 404; `AMOUNT_OUT_OF_RANGE`, `INVALID_INPUT` → 400; `RATE_LIMITED` → 429 with `Retry-After`.
- Rate limits per client IP: 30 quotes/min, 10 intents/min (Redis fixed window); fail open when Redis errors (log `rate_limit.unavailable`).
- CORS: only `WEB_ORIGIN` on `/v1/tip-quotes`, `/v1/tip-intents`, `/v1/tips/*`, `/v1/mock-provider/*`; methods GET/POST/OPTIONS; headers `content-type, authorization, idempotency-key`; no credentials.
- Status states: `waiting | paid | declined | checking | cancelled`; `checking` when the attempt is `UNKNOWN` or the tip is still unconfirmed 2 minutes after creation.
- Recognition: `localStorage` key `tipme.myTips.v1` = `{ v: 1, tips: [{ id, handle, at }] }`; written only on `paid` and only when opted in; never amounts or messages; copy "That's your {nth} tip. You've made {n} people's day. We see you." (singular forms for 1); no comparisons; never shown before paying.
- Expiry: attempt `CREATED`/`INITIATED` whose quote expired > 15 min ago → ask provider first; only if not paid: attempt `EXPIRED`, tip `CANCELLED`.
- Mock-checkout routes exist only when `PAYMENT_PROVIDER=mock` (already refused in production).
- Brand #7A32F9/white/black; WCAG 2.2 AA intent; every page noindex except existing marketing rules.
- No Git: checkpoint per task (format, lint, typecheck, test, plus `test:integration`/`test:e2e` where touched).

## Review Focus

1. **Double tap on "Tip"** sends two intent requests with the same `Idempotency-Key` → one tip, both responses carry the same token and checkout URL (Task 2).
2. **Status page opened in a new tab without the fragment** (e.g. link shared without `#t=`) → a clear "This receipt link is incomplete" state, no request without a token (Task 6).
3. **Quote expires while the supporter types a message** → intent returns 409 `QUOTE_EXPIRED`; the form silently fetches a fresh quote and asks to confirm the (unchanged) breakdown, never charging without a valid quote (Task 6).
4. **Corrupt or tampered `tipme.myTips.v1`** (non-JSON, wrong shape, huge) → ignored and rewritten safely; the page never crashes (Task 6).
5. **A late "paid" webhook for a tip already expired to CANCELLED** → never hidden: conflict path from PR-005 flags it; status shows `cancelled` and the expiry test asserts expiry always asks the provider first (Task 5).
