# PR-008 Recipient Accounts and Dashboard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Recipients sign up with a phone number and code, claim a handle and control their page. They see a dashboard with balance, trends and tips (with proof), withdraw pretend money, share a styled QR code, receive in-app and email tip notifications and a weekly report, and get surprise moments with fee-free or capped cash rewards. All of it uses pretend money and pretend delivery.

**Architecture:**

- **Postgres** (Drizzle migrations 0010+) holds users, sessions, sign-in codes, profile settings, notifications, a pretend outbox for messages and mail, reports, moments and reward credits.
- **The API** gains authenticated `/v1` routes protected by a session guard: an HttpOnly cookie plus an Origin check.
- **The worker** turns `tip.succeeded` outbox events into notifications and moments, and runs weekly and monthly jobs.
- **The web app** gains `/sign-in`, `/sign-up`, `/dashboard/*` and dev-only pretend inbox pages. `/@handle` moves from static demo data to the API, with on-demand revalidation.

**Tech Stack:** existing pins (Next 16.4.2, Nest 12.1.3, drizzle-orm 0.45.3, BullMQ 6.3.11, ioredis 5.11.1, zod 4.6.7, Playwright 1.64.1), plus new, registered dependencies:

- `libphonenumber-js` (phone normalisation);
- `qrcode` (QR generation);
- `jsqr`, dev only (QR decode tests).

**Spec:** `docs/superpowers/specs/2026-10-19-pr008-recipient-design.md`

## Global Constraints

### Pretend only

- No real SMS, WhatsApp, email, push, payout or billing.
- Pretend messenger and mailbox exist only when `MESSAGING_PROVIDER=mock`, which is refused in production, the same as `PAYMENT_PROVIDER=mock`.

### Sign-in

- Identity: E.164 phone number, unique. Input is normalised with default region `NG`.
- Codes: 6 digits, valid 10 minutes, only the latest code is valid, stored as an HMAC-SHA256 with `AUTH_CODE_SECRET` (at least 32 characters).
- 5 wrong attempts → 15-minute lockout.
- At most 3 codes per number per hour and 10 per IP per hour.
- Responses never reveal whether a number has an account.
- Delivery: WhatsApp first, SMS on simulated failure.

### Sessions

- 256-bit random token in cookie `tipme_session`:
  - `HttpOnly`, `SameSite=Lax`, `Path=/`;
  - `Secure` unless `WEB_ORIGIN` is `http://localhost*` or `http://127.0.0.1*`.
- Postgres stores only the SHA-256 of the token.
- Sliding 30-day expiry; the token is rotated on sign-in.
- Every state-changing authenticated request needs `Origin === WEB_ORIGIN` and the header `x-tipme-csrf: 1`.
- Authenticated CORS: `WEB_ORIGIN` only, `credentials: true`.

### Handles and page states

- Handle pattern: `/^[a-z0-9_]{3,30}$/` after lowercasing.
- Reserved handles: `admin api dashboard sign-in signin sign-up signup tipme support help legal tip tips mock-checkout people about-preview how-it-works for-creators for-professionals design-system preview-states ops settings me www`.
- A deleted handle is held for 90 days.
- Page states: `live | not_live | deleted`. New pages are `not_live`.
- Not-live, deleted, suspended and unknown handles all render the same "This page isn't available right now" screen.

### Profile details

- Phone and email visibility default to **private**. Bio and socials default to **public**.
- Socials: `https://` URLs on `facebook.com`, `www.facebook.com`, `instagram.com`, `www.instagram.com`, `x.com` or `twitter.com` only.
- Bio: at most 280 characters. Display name: 1–60 characters. Role: at most 60 characters.

### Money and rewards

- Integer minor units and decimal strings on the wire.
- Ledger postings go only through `postLedgerTransaction`.
- **Available balance** = `recipient_payable` credits − debits − the sum of that recipient's payouts in `REQUESTED` or `PROCESSING`.
- Confirming money (tips `PENDING_VERIFICATION`, plus `AWAITING_PAYMENT` with an attempt `PENDING`) is shown separately, never inside the balance.
- Reward configuration lives in `packages/domain/src/rewards.ts` (exact values in Task 11).
- Lifetime cap: cash bonuses + waived platform fees ≤ 50% of the platform fees that recipient has earned TipMe.
- Monthly cash budget: `REWARD_CASH_BUDGET_MINOR_PER_MONTH` (default `25000000`, i.e. ₦250,000).

### Time

- Day, week (ISO, Monday start) and month boundaries use `Africa/Lagos`.
- Weekly report: Monday 07:00 Lagos. Monthly job: the 1st, 07:00 Lagos.

### Privacy

- Never log or trace phone numbers, emails, codes, session tokens, messages or the `Authorization`/`Cookie` headers.
- Public and shareable output never names supporters.
- Recipients can read and change only their own data (server-side checks).

### Copy

- Recognition and moment copy celebrates and never compares with other people.
- Every dashboard and public page keeps the "Pretend payments" label.

### Gates

- No Git: one checkpoint per task (format, lint, typecheck, test, plus `test:integration` / `test:e2e` where touched).
- Brand #7A32F9/white/black, WCAG 2.2 AA, 320 px reflow, LCP ≤ 2.0 s (lab).

## Review Focus

These are the most likely ways a real user gets hurt, each with the task that pins it:

1. **Sign-in in a real browser across web :3000/:3100 and API :4000/:4100.**
   - The cookie must be set and sent, and survive a reload.
   - A forged cross-site POST without the Origin and CSRF header must be refused.
   - Pinned in Task 4 (e2e) and Task 2 (integration).
2. **Local-format phone numbers.**
   - "0803 123 4567" and "+234 803 123 4567" are the same person and must not create two accounts.
   - Pinned in Task 1.
3. **Switching to not live while the page is cached.**
   - A visitor sees "isn't available" within 5 s, and a tip started on an already-open page is refused (`TIP_NOT_PAYABLE`).
   - Pinned in Task 3 (API) and Task 4 (e2e).
4. **Two withdrawals at once.**
   - Two concurrent requests whose sum exceeds the available balance: exactly one succeeds, the other gets `INSUFFICIENT_BALANCE`.
   - Pinned in Task 6.
5. **Two tips crossing the same milestone at the same moment.**
   - Exactly one moment and one bonus, and the last fee-free credit is used once.
   - Pinned in Task 11.
