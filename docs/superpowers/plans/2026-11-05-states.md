# States and Feedback Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the shared tinted `Notice` box and `EmptyState` with TipMe's two state concepts, migrate every one of the 120 places on the States map, add the standing warning, build the visual and press feedback, and give connection failures a mechanism (offline detection, send on reconnect, one quiet retry). The new connection strings ship as their own PR, held for the owner's yes.

**Architecture:** Front end only. Branch `feat/states` (worktree `.worktrees/states`, from `origin/dev` at `d0325dd`). The connection mechanism lives in `apps/web/src/lib/connection.ts`, and its copy lives in a separate file so the strings can change in one place. No API, contract, database or payment change.

## Global Constraints

- **Rules for both concepts** (StatesConcepts "Rules for both"): no tinted alert boxes; no "!" or "✓" in front of words; colour is never the only signal, so every state has words; reassuring lines only where the code proves them (table above); errors are announced (`role="alert"`) and successes politely (`role="status"`), as today.
- **Which concept where:**
  - **B, the key:** saves, copy link, quick retries, and small refusals of a single click (settings saves, message controls, report a page, unsubscribe).
  - **A, the slip:** anything about money (tip not sent, withdrawals), account safety (recovery, bank account, handle change) and every staff action in `/ops` (dense slips).
  - **Page-level errors** (a screen that couldn't load) are an error slip with no stamp.
  - **Neutral notes** are a neutral slip.
  - **Standing warnings** use the new `StandingWarning`.
  - **Empty states:** `EmptySlip` on public and recipient pages, `EmptyWell` in `/ops`.
- **Words don't change** in this plan except: the strings marked _Proposed_ in owner question 5; the connection strings in Task 17 (held); and one removal: the "✓ " and "! " prefixes, which go.
- **Materials:**
  - `components.css` holds no hex colour (`packages/ui/test/primitives.test.mjs` already asserts this). New colours are tokens in `tokens.css`, each declared once (`design-tokens.test.mjs`).
  - Purple stays a signature material: a lamp, a stamp, a selected key. Never a background wash.
  - Touch targets are at least 44px, including the "Try again" half of a split key.
- **Motion:**
  - Press, settle and shake use `--duration-tactile` and `--duration-component`.
  - The shake runs once, only at a field, and never on a repeat error.
  - `prefers-reduced-motion: reduce` removes every shake and settle movement. The words and lamps still change at once.
- **Forced colours:** every slip, warning, well, lamp and split key keeps a `CanvasText` edge. Lamps get a border so they stay visible.
- **Live regions stay mounted** where they are today (for example `status-view.tsx:228`–`:230` and `notifications.tsx:79`). A region inserted together with its text is often not announced.
- **Focus:** when a key turns into a split "Try again" key, focus moves to "Try again" if the pressed key had focus. `ActionOutcome` keeps moving focus to its outcome (`action-outcome.tsx:28`–`:30`).
- **Retry safety** (financial invariant: "Never retry non-idempotent external money movements blindly"):
  - **Retried once, quietly:** the tip intent (same idempotency key and body), the tip quote, the sign-in verify, the welcome profile `PATCH` and `PUT /v1/me/page/state`.
  - **Never retried quietly:**
    - withdrawals (`POST /v1/me/withdrawals`);
    - sending a code (`POST /v1/auth/code`: a second code replaces the first, and `email-sign-in.ts:146`–`:159` only accepts the latest);
    - every `/ops` action;
    - bank-account changes.
  - **Sent on reconnect** only on the same surfaces as the quiet retry, and only for a tap the person made while offline.
- Users never see the payment provider's name: say "our payment partner" (`apps/web/test/no-provider-names.test.mjs`).
- No screen implies regulatory approval (`docs/00-DECISIONS.md`).
- Copy: sentence case, plain words, active voice, no em dashes, curly apostrophes as in the code today.
- **Baselines:** only an intentional design change updates a screenshot baseline. Run the visual spec without update mode first, inspect the diffs, explain the change in the commit, then `--update-snapshots` (`VISUAL-QUALITY-GATE.md`). This plan intentionally changes `tests/e2e/design-system.visual.spec.ts-snapshots/*` (Task 8) and `profile.visual.spec.ts-snapshots/*` only if a profile error is in frame (it is not today).
- Every web build deletes `apps/web/.next/cache` first: a cached build served stale CSS on 3 Nov 2026.
- `Notice` and `EmptyState` stay exported until Task 18. No new code may import them from Task 1 on: the migration guard test (Task 9) lists each migrated file.

### Task 4: `ResultKey`, `StateLine` and `useKeyResult` (Concept B)

The key you pressed shows the result on its own face. The explanation is one plain line with no box.

**Interfaces:**

```ts
export type KeyResult =
  | { kind: 'done'; label: string } // purple lamp, label e.g. "Saved.", springs back
  | {
      kind: 'failed';
      label: string;
      detail?: string; // red lamp in a dark window
      retryLabel: string;
      onRetry(): void;
    }; // the right half is a real button
/** A Button that can show its result. All Button props pass through to the key at rest. */
export function ResultKey(
  props: ComponentPropsWithRef<'button'> & {
    variant?: 'primary' | 'secondary' | 'quiet' | 'continue';
    result?: KeyResult | null;
  },
): JSX.Element;
/** One result at a time; a done result clears itself after settleMs (FeedbackMoments: about 2 s). */
export function useKeyResult(settleMs?: number /* 2000 */): {
  result: KeyResult | null;
  done(label: string): void;
  failed(result: Omit<Extract<KeyResult, { kind: 'failed' }>, 'kind'>): void;
  clear(): void;
};
/** The one plain line under a key. Always mounted, so a screen reader hears the change. */
export function StateLine(props: {
  tone: 'error' | 'status';
  children?: ReactNode;
  id?: string;
  /** The key face already shows it ("Saved."); the words stay for screen readers. */
  visuallyHidden?: boolean;
}): JSX.Element; // <p class="tm-state-line [sr-only]" role="alert|status">
```

**Rendering:**

- **At rest:** exactly `Button` (same classes, `data-material`).
- **`done`:**
  - The same `<button>` gets `data-result="done"` and class `tm-key-result--done`. Its content is `<Lamp tone="purple"/>` plus the label.
  - It renders in the pressed position (`translateY(2px)`, `--shadow-raised-continue-pressed`, dark `#141210` face as on the board, via a new token `--key-face-dark`, added in Task 1's token test).
  - It stays clickable.
- **`failed`:**

```html
<div class="tm-key-result tm-key-result--failed" data-result="failed">
  <span class="tm-key-result__face"
    ><Lamp tone="red" />{label}<small>{detail}</small></span
  >
  <button type="button" class="tm-key-result__again">{retryLabel}</button>
</div>
```

- The original key unmounts. If it had focus, `ResultKey` focuses `__again` (a `useEffect` on `result`).
- The face is `display: grid; grid-template-columns: 1fr auto`, min-height 52px. `__again` is at least 44px.
- The face text wraps at 320px (no `white-space: nowrap`).

- **Motion:** `done` settles with `transition: transform var(--duration-tactile) var(--ease-physical)`. With reduced motion there is no transform, and only the lamp and label change.
- **Forced colours:** `__face` gets a `CanvasText` border, and `__again` becomes `ButtonText` on `ButtonFace`.

```ts
// lib/connection.ts
type Answer = { ok: boolean; code?: string };
/** Where a request may be retried once quietly and sent again on reconnect. Nothing else is. */
export const QUIET_RETRY = [
  'tip-intent',
  'tip-quote',
  'sign-in-verify',
  'welcome-profile',
  'welcome-live',
] as const;
export type RetrySurface = (typeof QUIET_RETRY)[number];
export function retryable(surface: string): surface is RetrySurface;
/** 'offline' when the browser says so; 'no-answer' when online but the API couldn't be reached; else null. */
export function connectionProblem(
  answer: Answer,
  online: boolean,
): 'offline' | 'no-answer' | null;
/**
 * Sends; on NETWORK while online, waits 400–800 ms (jittered, like session-client.ts:33) and sends
 * the SAME request once more. Never retries when offline (the caller waits for reconnect instead),
 * and never for a surface outside QUIET_RETRY.
 */
export async function sendWithOneRetry<R extends Answer>(
  surface: RetrySurface,
  send: () => Promise<R>,
  options?: {
    online?: () => boolean;
    wait?: (ms: number) => Promise<void>;
    random?: () => number;
  },
): Promise<{ result: R; retried: boolean; firstWasNetwork: boolean }>;
/** Runs `run` once on the next 'online' event. Returns a cancel function. */
export function onReconnect(
  target: Pick<Window, 'addEventListener' | 'removeEventListener'>,
  run: () => void,
): () => void;

// components/use-online.ts ('use client')
/** navigator.onLine with the online/offline events; true on the server and before hydration. */
export function useOnline(): boolean; // useSyncExternalStore
```
