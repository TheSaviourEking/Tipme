# PR-004 Traceable API and Worker Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One connected OpenTelemetry trace and matching JSON logs from an API request through a BullMQ worker job, with truthful health, clean errors, limits, metrics and no private-data leakage.

**Architecture:** A new framework-free `packages/observability` owns the OTel SDK, pino logger, config parsing and trace-context propagation. `packages/contracts` gains zod schemas for every shared shape. The Nest API (`createApp(config)`) and the BullMQ worker (`startJobWorker(config)`) both preload telemetry, and the trace context travels inside the job payload.

**Tech Stack:** Node 24.22.0, Nest 12.1.3 (ESM), zod 4.6.7, OpenTelemetry (api 1.9.1, SDK 0.222.0 / 2.11.0), pino 10.4.0, BullMQ 6.3.11, ioredis 5.11.1, pg 8.23.1, Jaeger v2 (Docker), `node --test`.

**Spec:** `docs/superpowers/specs/2026-10-18-pr004-observability-design.md`

No other new runtime dependency without updating ADR-0005. Install with `pnpm install` only after the manifest edit for the task that needs it.
- Every command runs with Node 24.22.0 first on `PATH` (`export PATH=$HOME/.npm/_npx/fee7060b69ab3f2d/node_modules/node/bin:$PATH`, or `nvm use`).

- Existing behaviour stays green: `GET /health` → `200 {"status":"ok","service":"api"}`; worker prints `worker.started`/`worker.stopped` and exits 0 on SIGTERM/SIGINT; PR-003 web suites.

- Unit tests (`pnpm test`) need no infrastructure. Integration tests (`pnpm test:integration`) need `pnpm infra:up`.

## Review Focus

1. **Redis down while the probe is POSTed:** the API must answer `503 DEPENDENCY_UNAVAILABLE` within 3 s, not hang on ioredis's offline queue (Task 6).
2. **A hostile `traceparent` header** (garbage, or 10 KB long) is ignored, a fresh trace starts and the request succeeds (Task 5).
3. **Malformed JSON body:** `400 VALIDATION_FAILED`, not 500, and the raw body is not echoed (Task 5).
4. **Unknown or malformed `jobId`** on the status route: 404 for an unknown UUID, 400 for a non-UUID (Task 6).
5. **A corrupt job payload in Redis** fails immediately as unrecoverable, without the retry loop, and is logged with the reason `invalid_payload` and no data (Task 7).
