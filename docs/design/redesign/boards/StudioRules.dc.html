What stays fixed, what people can design, and what keeps it good

Owner, 12 Nov: “They should be able to make custom UI but no bad ones.” Earlier: “make it impossible for the user to build a bad page.” So: guardrails, not presets. People choose freely within a system that corrects what would break and refuses to publish what it can’t correct. A supporter should still recognise TipMe’s tip block, its fees and its report link on any page, however it’s designed. Upload rules are read from origin/dev today (apps/api/src/profiles/image-upload.ts). Proposed

Always TipMe (locked)

  • The tip block: TipMe’s own colours, fonts and shape, in the right rail on wide screens and straight after the name on phones. None of the person’s colours or fonts reach it. Only its amounts change, through today’s Pro tip amounts.
  • How fees are shown: the same line and the same full total before paying, on every page.
  • The Pro badge, after the handle; it can’t be moved, recoloured or hidden.
  • “Report this page” and the footer’s Privacy and Terms links (and “Learn about this preview” when it shows).
  • Name, photo and handle at the top, so a page can’t pretend to be someone else’s.
  • Closed tipping, “not taking tips yet” and the pilot notice show exactly as today.

Theirs to design, and the guardrail on each

Colour
Any 1 or 2 brand colours. The engine makes every page, card, border and text colour from them (OKLCH shades of the same hue), so every pair passes AA: 4.5 to 1 for text, 3 to 1 for large text and controls, on the light and the dark page. A colour that can’t carry text becomes an accent, with one plain sentence saying so.
Fonts
A library of 14 self-hosted families (no font request to any other site). At most 2 per page: one for headings, one for text. Display faces are headings-only. Every font shows ₦ and Nigerian letters such as ẹ, ọ, ṣ.
Sizes
From a type scale (Compact, Standard, Roomy), each size clamped between a phone minimum and a desktop maximum. Line length (up to 68 characters) and spacing follow from it. No size is ever typed in.
Layout
Rows on a 12-column grid: 1, 1:1, 2:1, 1:2 or 1:1:1 columns; blocks in each column; spacing S, M or L; backgrounds Page, Card, Colour or Photo; any order. Phones get one column by rule.
Blocks
Text, Photo, Gallery, Video, Services, Events, Links, Quote, Supporter wall; each with a few variants. Limits on every list and every text.
Photos
Smart crop around a focal point, a minimum size, and a shade under any text placed on a photo.
Corners
Square, Soft or Round.

Never

  • No custom HTML, CSS or JavaScript; no tracking pixels or third-party scripts. Everything people type is shown as plain text.
  • No free positioning, no pixel sizes, nothing overlapping; nothing over, inside or in front of the tip block.
  • No second payment button, no “pay for this service”, no goal or target. TipMe takes tips, not orders.
  • No publishing while the design check fails. There is no “publish anyway”.

The design check

One check, shared by the editor, the API and publishing. It runs on every edit and again on the server before publishing. Each problem comes with a one-click fix.

  • Contrast of every text, link and control, light and dark, including text on photos.
  • Fits phones: no overflow or clipped text from 320 px, long words included.
  • Fonts and sizes: 2 families at most; headings in order.
  • Crowding: too many blocks in a row or column.
  • Photos: too small for their spot; missing descriptions.
  • Page weight: 1.5 MB first load on a phone.
  • Empty or broken blocks, videos and links.

Exists Photos use today’s upload: JPEG, PNG or WebP up to 5 MB, never SVG, re-encoded to WebP so metadata such as EXIF location is dropped.

Proposed Videos come from an allow-list (YouTube, TikTok, Audiomack), shown as a TipMe-drawn still; the other site loads only after a tap. No video uploads.

Moderation: “Report this page” already exists (PROFILE_REPORT_REASONS); staff can remove any one photo.

The promise the build must test

With free choices there are too many designs to test one by one, so the build tests the rules. A property test makes thousands of random pages (random colours, fonts, rows, blocks and text lengths) and proves the guardrails always give AA contrast, no overflow from 320 to 1440 px, and a valid page. Every page is checked again when it’s published. A set of example pages is rendered in CI with accessibility and overflow checks and a few screenshots, and the page-weight budget is enforced.
