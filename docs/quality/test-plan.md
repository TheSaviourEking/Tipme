# Test plan

PRD §15 (9) and §14 "Acceptance, testing and release gates". What is tested, at which layer, how to run it, where each PRD requirement is covered, and what is **not** covered yet. It extends `docs/06-QUALITY-GATES.md` (the pyramid and the per-PR checklist) with the actual files.

Status: money is pretend. A passing suite proves the mock lifecycle, not a live payments release (`docs/00-DECISIONS.md`).

## How to run each layer

| Layer                                                                                                                                                  | Command                                                                                             | Needs                                                                                                                                                        |
| ------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Format, lint, types                                                                                                                                    | `pnpm format:check`, `pnpm lint`, `pnpm typecheck`                                                  | Node and pnpm only                                                                                                                                           |
| Unit tests, per package, plus the script tests                                                                                                         | `pnpm test`                                                                                         | Node and pnpm only                                                                                                                                           |
| Integration (real Postgres, Redis, API and worker in one process; files run in parallel, each process in its own copy of a migrated template database) | `pnpm test:integration` (`TEST_CONCURRENCY`, `TEST_SHARD=i/n`)                                      | `docker compose up -d postgres redis`                                                                                                                        |
| End to end (real browser against a built web app, API and worker)                                                                                      | `pnpm test:e2e`                                                                                     | Playwright's Chromium; the local Postgres and Redis                                                                                                          |
| Load against the PRD budgets                                                                                                                           | `pnpm test:load`                                                                                    | Docker (k6, pinned by digest) and the local Postgres and Redis                                                                                               |
| Dependency and secret scans                                                                                                                            | `pnpm audit --prod --audit-level=high`; gitleaks as in `.github/workflows/ci.yml`                   | Docker for gitleaks                                                                                                                                          |
| OpenAPI and generated documents are current                                                                                                            | `pnpm api:openapi --check`, `pnpm docs:generate --check`                                            | The built API                                                                                                                                                |
| Release check on any copy                                                                                                                              | `pnpm release:check --web … --api … [--full]` (`scripts/release-check.mjs`)                         | A running copy; `--full` only where `RELEASE_KIND=test`, and the admin part only when the release token and the `release_check` authenticator secret are set |
| Restore drill, point-in-time recovery drill, rollback drill                                                                                            | `docs/runbooks/backup-and-restore.md`, `deploy/scripts/pitr-drill.sh`, `scripts/rollback-drill.mjs` | Docker; the staging stack                                                                                                                                    |

## The PRD's mandatory money tests

From `docs/03-DOMAIN-AND-PAYMENTS.md`. Most have a test; the ones marked **Partly** or **Not yet** say what is missing.

These check one intent, one tip and one attempt; the single posting follows from the one attempt and is checked by the duplicate-event tests below                                                                                                                                                               |
| Same provider event twice → one transition and one posting                         | `tests/integration/scenarios.test.mjs` (4), `tests/integration/webhooks.test.mjs`, `packages/database/test/integration/provider-events.test.mjs`                                                                                                                                                                                                                                                                                                                                  |
| Out-of-order event after success → no downgrade                                    | `tests/integration/scenarios.test.mjs` (5), `packages/database/test/integration/provider-events.test.mjs`                                                                                                                                                                                                                                                                                                                                                                         |
| Provider timeout after a possible capture → `UNKNOWN`, reconcile, no second charge | `packages/payments/test/integration/mock-provider.test.mjs` (a retried start returns the same payment), `packages/database/test/integration/expire.test.mjs` (a start that timed out is looked up by its attempt id, and recorded as paid if it was, before any cancel), `tests/integration/scenarios.test.mjs` (7), `tests/integration/reconcile-flow.test.mjs`. | An expired or changed quote → rejected, re-quoted                                  | `packages/database/test/integration/intents.test.mjs`, `tests/integration/checkout-api.test.mjs` ("expired and used quotes are refused")                                                                                                                                                                                                                                                                                                                                          |
| A database failure after the provider's notice → recoverable, no false receipt     | `tests/integration/webhooks.test.mjs` ("when the database is unavailable the provider is asked to retry", "a database failure part-way through leaves no partial rows and asks for a retry": 503 and a full rollback), `packages/database/test/integration/outbox-relay.test.mjs`. **Not yet:** a test that replays the event after the database recovers                                                                                                                         |
| Debits equal credits for every operation and currency; reversals link back         | **Partly.** Balancing: `packages/domain/test/ledger.test.mjs`, `packages/database/test/integration/invariants.test.mjs`, `packages/database/test/integration/provider-events.test.mjs`. | Two withdrawals at once cannot spend the same money                                | `packages/database/test/integration/withdrawals.test.mjs`                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Two reconcilers at once book a payment once                                        | `packages/database/test/integration/reconcile.test.mjs`                                                                                                                                                                                                                                                                                                                                                                                                                           |

The provider scenarios (succeed, decline, pending, duplicate, out of order, wrong amount, no reply, forged) are the mock provider's, driven by `scripts/mock-pay.mjs` and the mock checkout page.

## Quality gates (PRD §14)

| Gate                                   | How it is checked                                                                                                                                                                                                                                                                                                                                       |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Accessibility** (WCAG 2.2 AA target) | axe checks inside the screen tests (each new screen adds one), plus `tests/e2e/quality.spec.ts`: every route reflows at 320 px (the equivalent of 400% zoom), reduced motion switches animation off, and keyboard use of the amount choices keeps focus. The release check repeats axe on the deployed copy (`tests/release/read-only.spec.ts`)         |
| **Performance**                        | The release check measures Largest Contentful Paint on a throttled phone (budget 2.0 s); the load test holds profile reads to 200 ms, checkout initialisation to 400 ms and dashboard reads to 300 ms at the 95th percentile, with fewer than 0.1% server errors (`tests/load/budgets.json`); real visits report LCP, INP and CLS to the admin Overview |
| **SEO**                                | `robots.txt` and the sitemap are tested (`apps/web/test/seo.test.mjs`); private pages are checked to be `noindex` by the release check                                                                                                                                                                                                                  |
| **Security**                           | The threat model's evidence column (`docs/security/threat-model.md`); the access matrix tests; the security-header test in `tests/e2e/quality.spec.ts`; dependency and secret scans in CI                                                                                                                                                               |
| **Operations**                         | Alerts every 15 minutes; the restore, point-in-time recovery and rollback drills; runbooks in `docs/runbooks/`                                                                                                                                                                                                                                          |
| **Accounting**                         | Balanced ledger tests; reconciliation tests; the issues inbox for mismatches                                                                                                                                                                                                                                                                            |
| **Contracts**                          | The OpenAPI document is generated from the routes and compared with them (`tests/integration/openapi.test.mjs`); error codes are a fixed list in `packages/contracts/src/errors.ts`                                                                                                                                                                     |

## Test data and environments

- **Local and CI** use a throwaway Postgres database (`openTestDatabase` resets it) and a Redis with a unique queue prefix per test file, so files cannot disturb each other. Integration tests run one file at a time (`--test-concurrency=1`).
- **The mock provider** replaces the payment processor and the pretend inbox replaces SMS and email. Neither can move real money or send a real message.
- **Staging** runs the same checks through the release check. Its full mode creates a rehearsal page, tips it, withdraws and resolves an issue, tags everything as a rehearsal, hides it from every total, and never runs on a copy that says `RELEASE_KIND=live`.
- **Production** is only ever checked read-only.
- Tests never use real phone numbers, cards or secrets. Fixtures are fake, and a secret scan covers the history.

## Keeping it true

- A pull request that adds a route, a state, a permission or a money rule adds or updates a row here and in the access matrix, the state-machine document or the threat model. Generated parts (`pnpm docs:generate`) are checked by `scripts/generate-docs.test.mjs`.
- Every file named in these documents must exist; that test fails when a test is renamed or removed without updating the document.
- A bug fix starts with a test that fails.
